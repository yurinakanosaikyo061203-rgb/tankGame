戦車ゲームのコード読本

自分で作っているゲームのコードを、上から順に読めるようになるための資料です。Unityでコードを開いて、横に並べながら読んでください。

この授業のゴール

読み終わったら、次のことを自分の言葉で説明できるようになります。

  1. コードの中の「変数」「if」「関数」が何をしているか
  2. Wキーを押してから戦車が前に進むまでに、コードのどこを通るか
  3. 画面の「速度」と「ギア」の数字が、どんな計算で決まるか
  4. 敵の戦車が相手を選び、追いかけ、撃つまでの流れ
前提知識
小学校の算数（かけ算、わり算、小数、四捨五入、速さ）と、中学1年のマイナスの数が分かれば読めます。プログラミングの言葉は、この資料の中で1つずつ説明します。物理（理科の「力」の計算）は使いません。

AIが書いたコードを、自分のコードにする

このゲームのコードには、AIに書いてもらった部分がたくさんあります。動くけれど、どうして動くのかが分からない。そんな状態を、1行ずつ読んで「分かる」に変えていくのが今日の目標です。

コードを全部いっぺんに読む必要はありません。どのファイルを読むときも、次の3つだけを探します。

1. いつ呼ばれるかUnityがどのタイミングでこの部分を動かすのか
2. 何の数を作るか「前後」「左右」「速さ」など、どんな数を計算しているのか
3. だれに頼むか作った数を、どの部品に渡して戦車を動かすのか

3つを探していくと、どの戦車のコードも同じ順番で動いていることが分かります。

コードを読むための道具

STEP1

変数は「名前のついた箱」

プログラムは、数や文字を「変数」という箱に入れて使います。箱には名前と、入れられるものの種類（型）が決まっています。

Player/PlayerTankMovement.cs
[Header("戦車のスペック設定")]
[SerializeField] private float horsepower = 500f;     // 500馬力固定
[SerializeField] private float maxSpeed = 14f;         // 最高時速 約50km/h固定
[SerializeField] private float maxBackSpeed = 3f;      // 後退時の最高速度
[SerializeField] private float rotateSpeed = 65.0f;    // 旋回速度

[Tooltip("旋回時に自動で加える前進の強さ（信地旋回のふくらみ具合）")]
[SerializeField] private float turnForwardPower = 1.0f;

[Header("オーディオ設定")]
[SerializeField] private AudioSource audioSource;
[SerializeField] private AudioSource shiftSoundSource;
[SerializeField] private AudioClip gearShiftClip;
private bool isAccelerating = false;

11行目を分解して読んでみます。

書いてあること意味
float箱の種類。小数を入れられる箱
horsepower箱の名前。英語で「馬力」
= 500f最初に500を入れておく。fは「float型の数です」という印
;文の終わり。日本語の「。」と同じ
// 500馬力固定コメント。//から後ろは人間向けのメモで、コンピューターは読まない

このコードには、ほかの種類の箱も出てきます。

型入れられるものこのゲームでの例
float小数最高速度maxSpeed = 14f
int整数画面に出す速度displaySpeed
booltrue（はい）かfalse（いいえ）だけエンジンをふかしているかisAccelerating
string文字ギアの名前"1速"

[SerializeField]が付いた変数は、Unityの「インスペクタ」という欄に表示されます。コードを書きかえなくても、インスペクタで数字を変えられます。

つまずきポイント

コードに書いた500fは「最初の値」です。インスペクタで別の数字にすると、ゲームではインスペクタの数字が使われます。コードとゲームの動きが合わないときは、まずインスペクタを見てください。

名前の前に_（アンダーバー）が付いた_rigidbodyのような変数もあります。これは「このファイルの中だけで使う箱」の目印として付けられています。付けなくても動きは同じです。

STEP2

ifは「もし〜なら」

ゲームでは「キーが押されていたら進む」のように、条件によってやることを変えます。そのときに使うのがifです。

Player/PlayerTankMovement.cs（ギアが変わったら音を鳴らす部分）
if (CurrentGear != previousGear)
{
    if (shiftSoundSource != null && gearShiftClip != null)
    {
        shiftSoundSource.PlayOneShot(gearShiftClip);
    }
    previousGear = CurrentGear;
}

( )の中が正しいときだけ、そのすぐ下の{ }の中が実行されます。181行目は「今のギアが、前のギアと違ったら」という意味です。

記号読み方例
== ／ !=等しい ／ 等しくないCurrentGear != previousGear
< ／ <=より小さい ／ 以下displaySpeed <= 6
&&かつ（両方とも正しい）183行目
||または（どちらかが正しい）62行目
!〜ではない（正しいと正しくないを入れかえる）!_isBacking（下がっていない）
null「何も入っていない」という意味shiftSoundSource != null

183行目は「音を鳴らすスピーカーがあって、かつ、鳴らす音も入っていたら」という意味です。インスペクタで音を入れ忘れても、ゲームが止まらないようにしています。

もう1つよく出てくるのがMathf.Absです。これは中学1年で習う「絶対値」で、マイナスを取った大きさを返します。$|-1| = 1$、$|0.3| = 0.3$です。

つまずきポイント

=（1つ）と==（2つ）は意味が違います。=は「右の値を左の箱に入れる」、==は「同じかどうか比べる」です。187行目のpreviousGear = CurrentGear;は、今のギアを「前のギア」の箱にしまっています。

先生メモ

「雨が降っていて、かつ、傘を持っていたら、傘をさす」。&&はこの「かつ」なんだ。どちらか片方だけだと傘はささないよね。

STEP3

関数は「命令のまとまり」、呼ばれる時間が決まっている

いくつかの命令をまとめて名前をつけたものを「関数」といいます。private void Awake()から}までが、Awakeという名前の関数です。

Unityは、決まった名前の関数を決まった時間に自動で呼びます。自分で「動け」と書かなくても動くのはこのためです。

関数の名前呼ばれるときこの戦車での使いみち
Awakeゲーム開始時に1回（一番さき）使う部品を手元に用意する
Startゲーム開始時に1回（Awakeのあと）戦車の重さを32000 kgに決める
Update画面を1枚描くたびに1回エンジン音の高さを変える
FixedUpdate0.02秒ごとに1回（1秒に50回）戦車を押して動かす
Player/PlayerTankMovement.cs
private void Awake()
{
    _rigidbody = GetComponent<Rigidbody>();
    _transform = transform;
    _drive = new TankDrive(_rigidbody, 1f);
}

private void Start()
{
    _rigidbody.mass = 32000f; // 32トン固定
    _rigidbody.linearDamping = 1.0f;
    _rigidbody.angularDamping = 4.0f;
}

35行目のRigidbody（リジッドボディ）は、Unityが用意している部品です。重さや押す強さをもとに、物がどう動くかを自動で計算してくれます。戦車を動かすときは、この部品に「押して」と頼みます。

37行目では、STEP 5で読む運転係TankDriveを1台分つくっています。newは「新しく1つ作る」という意味です。

43行目のlinearDampingは、何もしないと速さが少しずつ減っていく設定です。44行目のangularDampingは、回転が少しずつ止まっていく設定です。

つまずきポイント

Updateが1秒に何回呼ばれるかは、パソコンの速さで変わります。FixedUpdateは、どのパソコンでもいつも0.02秒ごとです。

だから「押す」処理はFixedUpdateに書きます。Updateに書くと、速いパソコンほどたくさん押されて、戦車が速くなってしまいます。

先生メモ

Updateはパラパラ漫画の「ページをめくるたび」なんだ。めくる速さは人によって違うよね。FixedUpdateはメトロノーム。いつも同じリズムで鳴るから、行進の歩幅をそろえたいときはこっちを使うんです。

STEP4

キー入力を「−1から1の数」で受け取る

戦車を動かす最初の仕事は、どのキーが押されているかを知ることです。Unityはキーの状態を数で教えてくれます。

Player/PlayerTankMovement.cs（FixedUpdateの中）
float horizontal = Input.GetAxis("Horizontal");
float vertical = Input.GetAxis("Vertical");

// 旋回時（左右入力あり）かつ前後入力がない時、自動で前進パワーを代入
if (Mathf.Abs(horizontal) > 0.05f && Mathf.Abs(vertical) <= 0.05f)
{
    vertical = turnForwardPower;
}
変数押したキー入る数
vertical（前後）W／S／ どちらも押さない1／−1／0
horizontal（左右）D／A／ どちらも押さない1／−1／0

92〜95行目は「左右のキーだけ押していて、前後のキーは押していない」ときの処理です。このときverticalにturnForwardPower（1.0）を入れます。だからAやDだけを押しても、戦車は前に出ながら曲がります。

ここから先、プレイヤーの戦車はこの2つの数だけを見て動きます。キー入力は「前後」と「左右」の2つの数に直されると覚えておいてください。

つまずきポイント

GetAxisの数は、キーを押した瞬間に1になるわけではありません。0、0.3、0.7、1のように少しずつ変わります。

同じファイルのUpdate（59〜60行目）ではGetAxisRawを使っています。こちらは押した瞬間に1になります。名前は似ていますが別の関数です。

STEP5

運転係TankDriveに「押して」「曲がって」と頼む

2つの数ができたら、次は戦車を動かします。プレイヤーのコードは、自分で戦車を動かさずに運転係の_driveに頼みます。

Player/PlayerTankMovement.cs
// 1. 旋回（回転）処理
if (Mathf.Abs(horizontal) > 0.05f && Mathf.Abs(vertical) > 0.05f)
{
    _drive.Turn(horizontal, rotateSpeed);
}

// 2. 移動処理
float totalForce = horsepower * 1200f;

if (vertical > 0.05f)
{
    if (CurrentForwardSpeed < maxSpeed)
    {
        _drive.Push(totalForce * vertical);

116行目は「今の速さが最高速度より小さいなら、前に押して」という意味です。最高速度に届いたら、もう押しません。

頼まれた運転係のほうを見てみます。

Common/TankDrive.cs
public void Turn(float horizontal, float rotateSpeed)
{
    Quaternion turnRotation = Quaternion.Euler(0f, horizontal * rotateSpeed * Time.fixedDeltaTime, 0f);
    _rigidbody.MoveRotation(_rigidbody.rotation * turnRotation);
}

// 正の値で前進方向、負の値で後退方向に力をかける
public void Push(float force)
{
    _rigidbody.AddRelativeForce(Vector3.forward * (_facing * force), ForceMode.Force);
}

曲がる角度を計算してみる

Turnは、0.02秒ごとに少しずつ戦車の向きを変えます。1回に回す角度は、28行目の3つの数のかけ算で決まります。

$$\text{1回の角度} = \text{horizontal} \times \text{rotateSpeed} \times 0.02$$
記号意味
horizontal左右の数。Dなら1、Aなら−1
rotateSpeed1秒に回る角度。プレイヤーは65度
0.02FixedUpdateの間隔（Time.fixedDeltaTime）
Dを押しているとき、$1 \times 65 \times 0.02 = 1.3$度。1秒には50回呼ばれるので、$1.3 \times 50 = 65$度回ります。ちゃんと「1秒に65度」になりました。Aならマイナスなので、反対向きに回ります。

押す強さ

Pushは、35行目でRigidbodyに「戦車の前向きに押して」と頼んでいます。Vector3.forwardは「戦車から見た前」という向きです。

押す強さは110行目の「馬力 × 1200」です。プレイヤーは500馬力なので、$500 \times 1200 = 600000$になります。この数の単位は気にしなくて大丈夫です。「大きいほど強く押す」とだけ覚えてください。

つまずきポイント

押したぶんだけ、すぐ速くなるわけではありません。どれだけ速くなるかは、戦車の重さ（32000 kg）や、速さが自然に減る設定（STEP 3）も関係します。その計算はRigidbodyが全部やってくれます。

「× 1200」は、馬力を「押す強さ」の数に直すためにかけている倍率です。なぜ1200なのかは、コードに書かれていません。

先生メモ

空っぽのショッピングカートと、お米を積んだカートを同じ強さで押してみよう。重いほうは、なかなか速くならないよね。このゲームでも同じことが起きていて、その計算をUnityが代わりにやってくれているんです。

Pushの中の_facingは味方の戦車のための工夫。味方のモデルは後ろ向きに作られているから、−1をかけて前と後ろを入れかえているんだ。

STEP6

画面の「速度」と「ギア」

画面左下には「速度: 50 km/h」「ギア: 5速」のような表示が出ます。この数字は、戦車の今の速さから計算しています。

コードの中の速さはm/s（1秒に何m進むか）です。これを、ふだん車で使うkm/h（1時間に何km進むか）に直します。

$$\text{km/h} = \text{m/s} \times 3.6$$
1時間は3600秒なので、1時間に進む道のりは$\text{秒速} \times 3600$ mです。kmに直すと1000でわるので、$\text{秒速} \times 3600 \div 1000 = \text{秒速} \times 3.6$になります。
最高速度14 m/sなら$14 \times 3.6 = 50.4$。四捨五入して50 km/hです。12行目のコメント「最高時速 約50km/h」と合っています。

STEP7

最高速度へ少しずつ近づける（Lerp）

押すだけだと、最高速度のところでぴたりと止まりにくくなります。そこで速さが6 m/sを超えたら、速さそのものを目標の速さへ少しずつ近づけます。

Player/PlayerTankMovement.cs
float startBrakeSpeed = 6.0f - (pitchAngle * 0.2f);
startBrakeSpeed = Mathf.Clamp(startBrakeSpeed, 2.0f, maxSpeed - 1f);

if (CurrentForwardSpeed > startBrakeSpeed)
{
    float slopeWeight = 1.5f + (pitchAngle * 0.1f);
    slopeWeight = Mathf.Clamp(slopeWeight, 0.2f, 5.0f);

    _drive.ApproachSpeed(maxSpeed, Time.fixedDeltaTime * slopeWeight);
}

pitchAngleは、戦車が前後にどれだけ傾いているか（坂の角度）です。平らな道では0なので、startBrakeSpeedは6、slopeWeightは1.5になります。Mathf.Clampは「数が決めた範囲からはみ出さないようにする」関数です。ここからは平らな道で考えます。

Common/TankDrive.cs
public void ApproachSpeed(float targetSpeed, float t)
{
    Vector3 localVelocity = _transform.InverseTransformDirection(_rigidbody.linearVelocity);
    localVelocity.z = Mathf.Lerp(localVelocity.z, _facing * targetSpeed, t);
    _rigidbody.linearVelocity = _transform.TransformDirection(localVelocity);
}

41行目のMathf.Lerp（ラープ）がこのSTEPの主役です。「今の値から目標の値へ、残りの差のt倍だけ近づける」計算をします。

$$v_{\text{新}} = v + (v_{\text{目標}} - v) \times t$$
記号意味
$v$（ブイ）今の速さ（m/s）。英語のvelocity（速さ）の頭文字
$v_{\text{目標}}$目標の速さ。ここではmaxSpeed ＝ 14
$t$近づける割合。$0.02 \times 1.5 = 0.03$で、「残りの差の3%だけ近づく」という意味
$v_{\text{新}}$1回近づけたあとの速さ
今の速さが10 m/sのとき
1回目: $10 + (14 - 10) \times 0.03 = 10 + 0.12 = 10.12$
2回目: $10.12 + (14 - 10.12) \times 0.03 = 10.12 + 0.1164 = 10.2364$
1回目は0.12増えましたが、2回目は0.1164しか増えていません。目標に近づくほど、1回で増える量が小さくなります。
つまずきポイント

Lerpは一気に目標の値にはしません。毎回「残りの差の3%」だけ近づくので、ゆっくり目標に寄っていきます。

tには0から1までの数を入れます。t ＝ 1なら一気に目標の値になり、t ＝ 0なら何も変わりません。

40行目と42行目のInverseTransformDirectionとTransformDirectionは、向きの言いかえです。「地図で見て北へ何m/s」を「戦車から見て前へ何m/s」に直してから計算し、また地図の向きに戻しています。zが「戦車から見た前後」です。

STEP8

キーを離したらブレーキ（Brake）

前後どちらのキーも押していないと、142〜145行目で_drive.Brake()が呼ばれます。Mキーでスペック表を開いている間も、82〜86行目で同じブレーキがかかります。

Common/TankDrive.cs
public void Brake()
{
    Vector3 localVelocity = _transform.InverseTransformDirection(_rigidbody.linearVelocity);
    if (Mathf.Abs(_facing * localVelocity.z) > 0.1f)
    {
        _rigidbody.AddRelativeForce(Vector3.back * (_facing * localVelocity.z * 25000f), ForceMode.Force);
    }
    else
    {
        localVelocity.z = 0f;
        _rigidbody.linearVelocity = _transform.TransformDirection(localVelocity);
    }
}

ブレーキは2段階になっています。

1段階目は、速さが0.1 m/sより大きいときです。50行目で、戦車を後ろ向き（Vector3.back）に押します。押す強さは「速さ × 25000」です。

$$\text{ブレーキの強さ} = \text{速さ} \times 25000$$
10 m/sなら$10 \times 25000 = 250000$、2 m/sなら$2 \times 25000 = 50000$です。速さが5分の1になると、ブレーキも5分の1になります。中学1年で習う「比例」の形です。

2段階目は、速さが0.1 m/s以下になったときです。54行目で前後の速さを0にして、ぴたりと止めます。

つまずきポイント

0にしているのはz（戦車から見た前後の速さ）だけです。x（横すべり）とy（上下。坂から落ちるときなど）は、そのまま残ります。

先生メモ

自転車で坂を下っているとき、スピードが出ているほどブレーキを強くにぎるよね。そして最後は、足を地面について止まる。このBrakeは、その2つを順番にやっているんだ。

STEP9

タイマーで0.5秒ごとに「一番近い相手」を探す

敵の戦車には、キーを押す人がいません。代わりに、自分で相手を探して、自分で「前後」と「左右」の数を作ります。まずは相手探しです。

AI/EnemyTankAI.cs（Updateの最初）
_scanTimer += Time.deltaTime;
if (_scanTimer >= 0.5f)
{
    _scanTimer = 0f;
    FindNearestTarget();

    // ★【修正】自分（足元）からの視線ではなく、大砲（マズル）から狙えるかをチェックする
    if (_turretAI != null)
    {
        _hasLineOfSight = _turretAI.CheckMuzzleLineOfSight();
    }
    else
    {
        _hasLineOfSight = false;
    }
}

_scanTimerは、キッチンタイマーのような変数です。Time.deltaTimeは「前の画面から今の画面までにかかった秒数」です。これを毎回足していき、0.5秒たまったら相手を探して、93行目で0に戻します。+=は「今の値に足す」という書き方です。

画面が1秒に60枚なら、1回のTime.deltaTimeは約0.0167秒です。$0.5 \div 0.0167 \approx 30$なので、30回に1回くらい相手を探します。
AI/EnemyTankAI.cs（FindNearestTargetの後半）
float closestDistance = scanRadius;
Transform closestTarget = null;
foreach (Transform t in potentialTargets)
{
    float distance = Vector3.Distance(_transform.position, t.position);
    if (distance < closestDistance)
    {
        closestDistance = distance;
        closestTarget = t;
    }
}
_attackTarget = closestTarget;

候補は、プレイヤーと味方の戦車全部です（262〜273行目）。foreachは「候補を1つずつ取り出して、全部に同じことをする」という書き方です。そのたびに距離を測り、今までで一番近ければ記録を書きかえます。

候補までの距離が120 m、80 m、300 mのとき。最初の「一番近い距離」はscanRadiusの1000 mです。
120 < 1000なので120に書きかえ。80 < 120なので80に書きかえ。300は80より大きいので書きかえません。答えは80 mの相手です。

相手が決まったら、大砲の先から相手まで、間に壁がないかも調べます（99行目）。中身はEnemyTurretAI.csの73〜91行目で、Physics.Raycast（見えない線を引いて、途中で何かに当たるか調べる命令）を使っています。

つまずきポイント

1000 mより遠い相手しかいないと、closestTargetはnull（何もない）のままです。このとき敵は、192〜196行目でブレーキをかけて止まります。

毎回ではなく0.5秒ごとに探す理由は、コードには書かれていません。探す処理は重いので、回数を減らしていると考えられます。

先生メモ

クラスで一番背の高い人を探すとき、最初の人の身長をメモして、もっと高い人が来たらメモを書きかえるよね。最後にメモに残っていた人が一番。このコードは「背が高い」の代わりに「距離が短い」で同じことをしているんだ。

STEP10

角度を見て、AIが自分で「キー」を押す

敵は、相手のところまでの道をNavMeshAgent（ナブメッシュ・エージェント）というUnityの道案内係に探してもらいます。建物をよけた道を作ってくれて、次に向かう曲がり角を教えてくれます。

敵の戦車は、その曲がり角が自分から見て何度ずれているかを計算します。そして、その角度から「前後」と「左右」の数を作ります。

AI/EnemyTankAI.cs（FixedUpdateの中）
Vector3 localDir = _transform.InverseTransformDirection(targetDirection);
float angleToTarget = Mathf.Atan2(localDir.x, localDir.z) * Mathf.Rad2Deg;

float horizontalInput = 0f;
if (Mathf.Abs(angleToTarget) > 8f)
{
    if (angleToTarget > 0f)
    {
        horizontalInput = 1f;
    }
    else
    {
        horizontalInput = -1f;
    }
}

float verticalInput = 0f;
if (Mathf.Abs(angleToTarget) < 45f)
{
    verticalInput = 1f;
}

if (Mathf.Abs(horizontalInput) > 0.05f && Mathf.Abs(verticalInput) <= 0.05f)
{
    verticalInput = turnForwardPower;
}

231行目のMathf.Atan2（アークタンジェント・ツー）は、「右にどれだけ」と「前にどれだけ」の2つの長さから角度を出す道具です。中の計算は高校で習うので、今は「分度器のように角度を測ってくれる道具」と思っておけば大丈夫です。右にずれていればプラス、左ならマイナスの角度になります。

233〜255行目は、STEP 4のキー入力をAIが自分で作っている部分です。角度によって次のように決まります。

ずれの大きさhorizontal（左右）vertical（前後）押すキー
8度以下01Wだけ
8度より大きく、45度より小さいずれている側へ1か−11WとD（またはA）
45度以上ずれている側へ1か−10.5（turnForwardPower）D（またはA）だけ。ゆっくり前へ出る

曲がり角の場所と、AIが押す「キー」

angleToTarget-
horizontalInput-
verticalInput-
押すキー-

こうして作った2つの数をExecuteMovement（289〜319行目）に渡します。その中身はSTEP 5〜8と同じで、運転係の_driveに「押して」「曲がって」「止まって」と頼んでいます。

つまずきポイント

敵の押す強さは「馬力 × 1800」で、プレイヤーの「× 1200」とは違います（292行目）。敵の馬力は700なので、$700 \times 1800 = 1260000$です。ただし敵は53000 kgとプレイヤーより重いので、それだけで速いとは言えません。

先生メモ

人がキーボードで「Dを押す」代わりに、AIは「角度が8度より大きいから、horizontalに1を入れよう」と決めているんです。運転係のTankDriveから見ると、人が運転しているのかAIなのか区別がつかない。だから同じ運転係を使い回せるんだね。

STEP11

引っかかったら脱出する

敵の戦車が、壁や建物に引っかかって動けなくなることがあります。そのために「動いているはずなのに動いていない」状態を見張っています。

AI/EnemyTankAI.cs（Updateの中）
if (!_isBacking && !_isEscapingTurn && !_isEscapingForward)
{
    bool shouldMove = _agent.hasPath && (!_hasLineOfSight || distanceToTarget > attackDistance);
    _posCheckTimer += Time.deltaTime;
    if (_posCheckTimer >= 0.2f)
    {
        _posCheckTimer = 0f;
        float checkDist = Vector3.Distance(_transform.position, _lastPosition);
        if (shouldMove && checkDist < 0.12f)
        {
            _stuckTimer += 0.2f;
            if (_stuckTimer > 1.5f)
            {
                _isBacking = true;
                _backTimer = 1.5f;
                _stuckTimer = 0f;
            }
        }
        else
        {
            _stuckTimer = 0f;
        }
        _lastPosition = _transform.position;
    }
}

0.2秒ごとに、前の位置からどれだけ動いたかを測ります。動くべきなのに0.12 mも動いていなければ、_stuckTimerに0.2を足します。少しでも動いていれば0に戻します。

142行目は、1.5を「超えた」ら脱出を始めるという意味です。0.2を7回足すと1.4で、まだ超えません。8回足すと1.6で超えます。つまり「動けない」が8回続けて見つかったら脱出です。$8 \times 0.2 = 1.6$秒かかります。

脱出は次の順番で進みます。156〜187行目でタイマーを減らし、197〜211行目で実際に動かしています。

ふつうに走る0.2秒ごとに見張る
→
後ろに下がる1.5秒
→
その場で右に回る1.0秒
→
前に出る1.0秒
→
ふつうに走る道を探し直す
つまずきポイント

「今どの段階か」は、_isBacking、_isEscapingTurn、_isEscapingForwardという3つのboolの変数で覚えています。trueになるのは、いつも多くて1つだけです。

相手の近くで止まって撃っているとき（shouldMoveがfalseのとき）は、動いていなくても「引っかかった」とは数えません。

先生メモ

お掃除ロボットが家具の脚にはまったとき、ちょっと下がって、向きを変えて、また進むよね。あれと同じことを、タイマーを3つ使ってやっているんです。

STEP12

砲塔を相手に向けて撃つ

敵の砲塔（大砲が載っている、くるっと回る部分）はEnemyTurretAI.csが動かしています。狙う相手は、STEP 9でEnemyTankAIが決めたAttackTargetをそのまま使います。

AI/EnemyTurretAI.cs（Updateの中）
// 3. 自動射撃ロジック
_fireTimer += Time.deltaTime;

if (_aiMovement.HasLineOfSight && _fireTimer >= fireInterval)
{
    Vector3 forwardVector = turretObject.forward;
    Vector3 targetDir = (target.position - turretObject.position).normalized;

    if (Vector3.Angle(forwardVector, targetDir) < 5f)
    {
        StartCoroutine(Generate_Enemy_Bullet());
        _fireTimer = 0f;
    }
}

撃つ条件は3つあって、全部そろったときだけ撃ちます。

条件コード
大砲の先から相手まで、間に壁がないHasLineOfSight
前に撃ってから7秒以上たった_fireTimer >= fireInterval（fireIntervalは7）
砲塔の向きと相手の方向のずれが5度より小さいVector3.Angle(...) < 5f

砲塔は44〜48行目で、1秒に15度（turretRotateSpeed）ずつ相手のほうへ回ります。Quaternion.RotateTowardsは「決まった角度だけ、目標の向きへ回す」命令です。

相手が真横（90度）にいるとき、砲塔が向くまで$90 \div 15 = 6$秒かかります。向いたあとでも、前に撃ってから7秒たっていなければ撃ちません。

撃つときはGenerate_Enemy_Bullet（93〜133行目）が、発射音を鳴らし、大砲の先に炎を出し、弾を作ります。弾は1回分だけ待ってから、1秒に250 mの速さで飛び出します。

つまずきポイント

STEP 7のLerpは「残りの差の何%」ずつ近づきました。こちらのRotateTowardsは「毎回同じ角度」ずつ近づきます。だから砲塔は最後までゆっくりにならず、同じ速さで回ります。

味方の戦車を読む

CompanionTankAI.csも、敵とほぼ同じ形です。「一番近い相手を探す」「角度で左右を決める」「引っかかったら下がる」が出てきます。違うところは次のとおりです。

味方だけのしくみどこを読むか
150 m以内に敵がいれば敵へ、いなければプレイヤーへ向かうFixedUpdateのtargetPosition
プレイヤーから10 m以内なら止まるfollowDistance
味方どうしがくっつきすぎないように、離れる向きを足すComputeSeparationForce
モデルが後ろ向きなので、運転係に−1を渡しているAwakeのnew TankDrive(_rigidbody, -1f)

AIに書いてもらったコードを読むとき

コメントより、コードを信じる
「★【修正】」「★新設」のようなコメントは、直したときのメモです。その行が何をしているかの説明になっていないことがあります。迷ったらコメントは読み飛ばし、ifの条件を1つずつ日本語に直してみてください。たとえばshiftSoundSource != null && gearShiftClip != nullは、STEP 2の記号の表を使うと「スピーカーがあって、かつ音も入っていたら」と読めます。
数字を1つ変えて、動きを見る
STEP 6の「やってみよう」のように、インスペクタで数字を1つだけ変えて遊んでみましょう。予想どおりに変われば、そのコードを読めたことになります。
Debug.Logで中身をのぞく
気になる行のすぐ下にDebug.Log(angleToTarget);のように書くと、UnityのConsoleに変数の中身が表示されます。確かめたら、その行は消しておきます。
数字を決めた理由をコメントに残す
1200、1800、25000のような倍率は、なぜその数なのかがコードに書かれていません。決めた理由をコメントに書いておくと、あとで読み返したときに困りません。分からない数は、STEP 6の「やってみよう」のように数字を変えて動きを確かめましょう。
AIに質問するときは1か所ずつ
「このファイルを説明して」より「231行目のAtan2は何をしているの」のように、行を決めて聞くほうが分かりやすい答えが返ってきます。

確認問題

問1. 戦車を押す処理は、UpdateではなくFixedUpdateに書かれています。それはなぜですか。
答えを見る

FixedUpdateは、パソコンの速さに関係なく0.02秒ごとに呼ばれるからです。Updateに書くと、呼ばれる回数がパソコンによって変わり、戦車の速さも変わってしまいます。（STEP 3）

問2. 戦車が前に5 m/sで進んでいます。画面の速度表示とギアはどうなりますか。
答えを見る

$5 \times 3.6 = 18$なので「速度: 18 km/h」です。18は16〜25の範囲なので「ギア: 3速」になります。（STEP 6）

問3. 今の速さが12 m/s、目標の速さが14 m/s、近づける割合tが0.03です。Lerpを1回したあとの速さは何m/sですか。
答えを見る

$12 + (14 - 12) \times 0.03 = 12 + 0.06 = 12.06$ m/sです。（STEP 7）

問4. 敵の戦車から見て、次の曲がり角が左に30度ずれています。horizontalInputとverticalInputはいくつになりますか。
答えを見る

左なのでangleToTargetは−30です。絶対値30は8より大きいのでhorizontalInputは−1、45より小さいのでverticalInputは1です。押すキーはWとAです。（STEP 10）

大事なところ

  1. Unityは、決まった名前の関数を決まった時間に呼びます。戦車を押す処理は、いつも0.02秒ごとに呼ばれるFixedUpdateに書きます。
  2. どの戦車も、まず「前後」と「左右」の2つの数を作ります。プレイヤーはキー入力から、敵と味方は角度の計算から、この2つの数を作ります。
  3. 戦車を動かすのは、みんな同じ運転係TankDriveです。Pushで押し、Turnで曲がり、ApproachSpeedで速さを整え、Brakeで止まります。
  4. 画面の速度は、m/sに3.6をかけて四捨五入した数です。ギアはその数で決まる表示と効果音のためのもので、押す強さは変えません。
  5. 敵はタイマーで、決まった間隔ごとに考えます。0.5秒ごとに相手を探し、0.2秒ごとに引っかかりを見張り、7秒たつと次の弾を撃てるようになります。

結論

このゲームの戦車は、キー入力やAIの判断を、まず「前後」と「左右」の2つの数に直します。その数を運転係のTankDriveが受け取り、UnityのRigidbodyに「押して」「曲がって」と頼んで戦車を動かしています。どのファイルを読むときも「2つの数をどうやって作っているか」を探すと、流れを追いやすくなります。
