戦車AIのコード読本

戦車ゲームのコード読本の続きです。敵と味方の戦車が、建物などの障害物をどう扱っているかを読みます。今うまく動いていないところと、その直し方もまとめます。

この授業のゴール

読み終わったら、次のことを自分の言葉で説明できるようになります。

  1. 敵の戦車が「撃てるかどうか」を、見えない線でどう調べているか
  2. 敵の戦車が、建物をよける道をどこから受け取っているか
  3. 味方の戦車が、壁や仲間とのあいだをどう空けているか
  4. 敵が同じ場所で引っかかり続けるのはなぜか、どう直せばよいか
前提知識
コード読本のSTEP 1〜13を読んでいること。とくにSTEP 9〜STEP 11（相手を探す、角度でキーを押す、引っかかったら脱出する）を使います。計算は、小学校で習う円周の求め方（直径 × 3.14）まで使います。

敵の戦車と障害物

STEP1

敵のAIは2つのスクリプトでできている

敵の戦車は、シーンのE_50です。いちばん上のオブジェクトに、2つのスクリプトが付いています。EnemyTankAIは足まわりの係で、相手を探して走ります。EnemyTurretAIは砲塔の係で、砲塔を回して撃ちます。

2つの係は、おたがいの結果を使います。そのために、相手のスクリプトを最初に手元へ用意しています。

AI/EnemyTankAI.cs

{
    _rigidbody = GetComponent<Rigidbody>();
    _transform = transform;
    _drive = new TankDrive(_rigidbody, 1f);
    _agent = GetComponent<NavMeshAgent>();
    _turretAI = GetComponent<EnemyTurretAI>(); // 自動取得
}
AI/EnemyTurretAI.cs
private void Awake()

    _aiMovement = GetComponent<EnemyTankAI>();

120行目の_hasLineOfSightは「大砲の先から相手が見えているか」を入れておくboolです。見えていて200 m以内なら、122行目で道案内をやめて止まります。そうでなければ、127行目で相手の場所までの道を頼みます。

STEP2

大砲の先から「見えない線」を引く

「見えているか」を調べているのは、砲塔の係のCheckMuzzleLineOfSightです。足まわりの係が、0.5秒ごとにこの関数を呼びます。

AI/EnemyTurretAI.cs
public bool CheckMuzzleLineOfSight()
{
    if (_aiMovement == null || _aiMovement.AttackTarget == null || muzzlePoint == null)
    {
        return false;
    }

    Transform target = _aiMovement.AttackTarget;
    Vector3 startPos = muzzlePoint.position;
    Vector3 targetPos = target.position + Vector3.up * 1.5f;
    Vector3 dir = (targetPos - startPos).normalized;
    float dist = Vector3.Distance(startPos, targetPos);

    if (Physics.Raycast(startPos, dir, out RaycastHit hit, dist, _aiMovement.ObstacleLayer))
    {
        return false;
    }
    return true;
}

86行目のPhysics.Raycast（レイキャスト）は、見えない線を1本引いて、途中で何かに当たるかを調べる命令です。この線をRay（レイ）といいます。渡している数は次のとおりです。

渡すものこのコードでの中身
線の出発点startPos。大砲の先に置いたmuzzlePointの位置（81行目）
線の向きdir。大砲の先から、相手の足元より1.5 m上の点へ向かう向き（82〜83行目）
当たった物の記録out RaycastHit hit。何に当たったかが入る
線の長さdist。相手までの距離。相手より先は調べない
当たってよいものObstacleLayer。どのレイヤーの物に当たるか

途中で何かに当たると、87〜88行目でfalse（見えない）を返します。最後まで何にも当たらなければ、90行目でtrue（見える）を返します。

レイヤーは「グループの名札」

Unityのオブジェクトには、1つずつ「レイヤー」という名札が付いています。LayerMaskは、どの名札の物に線を当てるかを決めるチェック表です。インスペクタでは、E_50のEnemyTankAIにあるObstacle Layerの欄がこのチェック表です。

つまずきポイント

今のObstacle LayerはNothing（何もチェックしていない）です。線はどの物にも当たらないので、いつも「見える」になります。だから敵は、建物の向こうの相手にも撃ちます。建物の陰にいる相手に近づかず、その場で止まってしまうこともあります。

Defaultにチェックを入れればよい、というわけでもありません。このシーンでは、建物も戦車も同じDefaultレイヤーです。線が狙っている相手の戦車に当たって、いつも「見えない」になります。建物だけを別のレイヤーに分ける必要があります（直し方）。

STEP3

NavMeshは「通れる床の地図」

敵は、建物をよける道を自分では考えていません。UnityのNavMesh（ナブメッシュ）という地図を使って、道案内係のNavMeshAgentに道を探してもらっています。

NavMeshは「戦車が通れる床」だけを集めた地図です。シーンの床や建物から、エディタで前もって作っておきます。この作業を「焼く（Bake）」といいます。

道案内係には、道だけを聞く

地図は、壁から「半径」ぶん離して作られる

NavMeshを焼くときは、通る者の大きさを「半径」で決めます。壁から半径ぶんの帯は「通れない」として地図から削られます。だから道は、壁から半径ぶん離れた所を通ります。

今のNavMeshは、Unityが最初から用意している人間用の大きさで焼かれています。半径は0.5 mです。一方、戦車の当たり判定は、幅1.8 m、長さ4.5 mほどあります。

左の図のように、道どおりに走っても、車体の横が建物の角に当たります。半径を戦車に合わせて大きくすると、右の図のように道が角から離れます。

つまずきポイント

NavMeshAgentのインスペクタには「Obstacle Avoidance」という欄もあります。これは、ほかの道案内係とぶつからないように速さをずらす機能です。建物はよけません。このゲームのコードは道案内係の速さを使っていないので、この欄を変えても戦車の動きは変わりません。

シーンには、焼いた地図が6枚あります。どれもシーン全体を集める設定で焼かれているので、同じ地図が重なっていると考えられます。地図は1枚にしておくほうが安全です。

どれくらいの円で曲がれるか

敵の最高速度は15.3 m/s、曲がる速さは1秒に50度です。この速さのまま回り続けると、どれくらいの大きさの円を描くかを計算してみます。

1周（360度）するのにかかる時間は、$360 \div 50 = 7.2$秒です。
その間に進む道のりは、$15.3 \times 7.2 = 110.16$ m。これが円周です。
円周 ＝ 直径 × 3.14なので、直径は$110.16 \div 3.14 \approx 35.1$ m、半径は約17.5 mです。

角から0.5 mの道を、半径17.5 mの円でしか曲がれない戦車が走ります。曲がりきれずに外へふくらみ、建物にぶつかります。

先生メモ

自転車で急な角を曲がるとき、スピードを出したままだと外へふくらむよね。だから角の手前でブレーキをかけて、ゆっくり曲がる。今の敵は、そのブレーキを知らないんです。

STEP5

角に当たって動けなくなると、コード読本のSTEP 11で読んだ脱出が始まります。動けないのが1.6秒続いたら、次の3つを順番に行います。

AI/EnemyTankAI.cs（FixedUpdateの中）

{
    ExecuteMovement(0f, -1f);
    return;
}
if (_isEscapingTurn)
{
    ExecuteMovement(1f, 0f);
    return;
}
if (_isEscapingForward)
{

順番やること時間
1後ろに下がる（199行目）。最高でも4.2 m/s × 1.5秒 ＝ 6.3 mまで1.5秒
2その場で右に回る（204行目）。1秒に50度なので、約50度1.0秒
3まっすぐ前に全力で進む（209行目）。ハンドルは切らない1.0秒

向かう先は、150 m以内に敵がいれば敵（142行目）、いなければプレイヤー（146行目）です。敵がいなくてプレイヤーから10 m以内なら、133行目で止まります。

148行目で向かう先への向きを作り、150行目で「仲間から離れる向き」（STEP 7）を足しています。建物をよける向きは、どこにも足されていません。だから味方は、建物の向こうにいる相手へ、建物に向かってまっすぐ進みます。

つまずきポイント

味方の中にはNavMeshAgentが付いているものもあります。でも、CompanionTankAIはそれを一度も使っていません。付いているだけです。

STEP7

壁までの距離で、仲間との間隔を決める

味方もRayを使っています。ただし、敵のように「見えるか」を調べるためではありません。左右の壁までの距離を測って、仲間とどれくらい離れるかを決めています。

AI/CompanionTankAI.cs
private void CalculateSpaceByWallDistance()
{
    float minWallDistance = 100f;
    Vector3 leftDir = -_transform.right;
    if (Physics.Raycast(_transform.position, leftDir, out RaycastHit leftHit, 30f, wallLayer))
    {
        minWallDistance = Mathf.Min(minWallDistance, leftHit.distance);
    }

    Vector3 rightDir = _transform.right;
    if (Physics.Raycast(_transform.position, rightDir, out RaycastHit rightHit, 30f, wallLayer))
    {
        minWallDistance = Mathf.Min(minWallDistance, rightHit.distance);
    }

    float calculatedSpace = minWallDistance * 0.25f;
    _currentPersonalSpace = Mathf.Clamp(calculatedSpace, minPersonalSpace, maxPersonalSpace);
}

車体の真ん中から左と右へ、30 mの線を引きます。近いほうの壁までの距離を4分の1にした数が、仲間との間隔になります（198行目）。199行目のMathf.Clampで、間隔が決めた範囲からはみ出さないようにしています。範囲はインスペクタの値で、8 mから15 mです。

左の壁が12 mなら、$12 \times 0.25 = 3$ m。8 mより小さいので、8 mに引き上げられます。
30 m以内に壁がないときは、185行目の100がそのまま残ります。$100 \times 0.25 = 25$ mは15 mより大きいので、15 mに下げられます。
線は30 mまでしか届かないので、壁に当たったときの4分の1は、いちばん大きくても$30 \times 0.25 = 7.5$ mです。今の数値では、間隔は8 mか15 mのどちらかにしかなりません。

仲間が決めた間隔より近くにいると、ComputeSeparationForceが仲間から離れる向きを作ります。

AI/CompanionTankAI.cs（ComputeSeparationForceの中）
Vector3 diff = (_transform.position - companion.transform.position).normalized;
diff /= distance;
steering += diff;

228行目で、離れる向きを距離でわっています。距離が2 mなら半分、1 mならそのままの強さです。近い仲間ほど、強く離れようとします。

つまずきポイント

3台のうち2台は、線を当てるレイヤー（Wall Layer）がEverything（全部）です。壁だけでなく、仲間の戦車にも線が当たります。自分の車輪の当たり判定にも当たっているかもしれません。もしそうなら、間隔はいつも8 mになっています。Unityで確かめたいところです。

直し方

今うまく動いていないところ

ここまでで見つけたことを、起きることごとにまとめます。どれもまだ直していません。

起きること原因直し方
壁の向こうの相手にも撃つObstacle LayerがNothing（STEP 2）Obstacleレイヤーを作る
道どおりに走っても角に当たるNavMeshが半径0.5 mで、6枚重なっている（STEP 3）NavMeshを焼き直す
曲がりきれずに外へふくらむ大きく曲がるときも全力で押し、ブレーキをかけない（STEP 4）コードの案1
下がって、また同じ所で引っかかるいつも右に回ってまっすぐ出る脱出と、同じ道（STEP 5）NavMeshの焼き直しとコードの案2

味方が建物を回り込めない味方はNavMeshを使っていない（STEP 6）敵と同じ道案内を使う。変更が大きいので、別に相談する
味方が遠くで引っかかったまま遠いときは引っかかりを数えない（STEP 8）条件の意図を確かめてから決める

いちばん効くのは、NavMeshの焼き直しです。道が角から離れれば、ふくらみや引っかかりそのものが減ります。

Obstacleレイヤーを作る

  1. Edit > Project Settings > Tags and Layersを開き、空いているUser Layer（15番以降）にObstacleと名前を付けます。
  2. 建物や壁を選び、インスペクタ右上のLayerをObstacleにします。子オブジェクトも変えるか聞かれたら、「Yes, change children」を選びます。建物はプレハブの中にあるので、プレハブを開いて変えます。
  3. E_50を選び、EnemyTankAIのObstacle LayerでObstacleだけにチェックを入れます。
  4. 味方1台のWall Layerは、Everythingではなく一部のレイヤーだけを選んでいます。この1台にはObstacleのチェックを足します。
  5. プレイヤーを建物の陰に隠し、敵が撃たずに回り込んでくるかを確かめます。

地面や丘をObstacleに入れるかは、ゲームの作りで決めます。入れると、丘の向こうの相手も見えなくなります。

NavMeshを焼き直す

  1. Window > AI > NavigationのAgentsタブで、新しいエージェントを作ります。名前はTank、Radiusは2.5、Heightは3にします。2.5 mは、幅1.8 m、長さ4.5 mの車体がその場で回るときの円（対角線の半分、約2.4 m）より少し大きい値です。E_50のほうが大きければ、それに合わせます。
  2. ヒエラルキーの検索欄にt:NavMeshSurfaceと入れ、出てきたNavMeshSurfaceを全部外します（Remove Component）。Assets/_Project/Scenes/SampleScene/にあるNavMesh-*.assetの6つも消します。
  3. 戦車がいた場所が「通れない穴」にならないように、各戦車のいちばん上のオブジェクトにNavMesh Modifierを付け、ModeをRemove objectにします。
  4. 空のオブジェクトNavMeshを作ってNavMesh Surfaceを付けます。Agent TypeはTank、Collect ObjectsはAll Game Objects、Use GeometryはPhysics Collidersにして、Bakeを押します。
  5. E_50のNavMeshAgentのAgent TypeをTank、Radiusを2.5にします。
  6. Sceneビューで青い地図を見て、大事な道が消えていないかを確かめます。半径が大きすぎると細い道が消え、敵はそこを通れなくなります。
やってみよう

焼き直す前と後で、Play中にE_50を選び、SceneビューのAI NavigationオーバーレイでShow Pathをオンにしてみましょう。道の線が、建物の角からどれくらい離れたかを見比べられます。

確認問題

問1. 敵のObstacle LayerでDefaultだけにチェックを入れると、敵はどうなりますか。
答えを見る

このシーンでは戦車もDefaultレイヤーなので、線が狙っている相手の戦車に当たります。いつも「見えない」になり、敵は撃たずに近づき続けます。（STEP 2）

問2. 10 m/sの速さで、1秒に50度ずつ曲がり続けます。描く円の半径はおよそ何mですか。
答えを見る

1周に$360 \div 50 = 7.2$秒かかり、その間に$10 \times 7.2 = 72$ m進みます。直径は$72 \div 3.14 \approx 22.9$ mなので、半径は約11.5 mです。（STEP 4）

問3. 味方の戦車の右の壁が20 m、左の壁が26 mのところにあります。仲間との間隔は何mになりますか。
答えを見る

近いほうの20 mを使って、$20 \times 0.25 = 5$ mです。最小の8 mより小さいので、8 mになります。（STEP 7）

問4. 敵が脱出を終えたあと、また同じ角で引っかかるのはなぜですか。
答えを見る

脱出が終わると道を消し、同じ相手への道をもう一度頼みます。地図が変わっていないので、同じ角すれすれの道が返ってきて、また全力でその角へ向かうからです。（STEP 5）

大事なところ

  1. 敵は、大砲の先から相手へ見えない線を引いて「見えるか」を調べます。どの物に線を当てるかは、Obstacle Layerのチェック表で決まります。今はNothingなので、いつも「見える」になっています。
  2. 敵は、NavMeshという地図から次の曲がり角を受け取ります。地図は壁から半径ぶん離して作られます。今の半径は人間用の0.5 mで、戦車には小さすぎます。
  3. 敵は、大きく曲がるときも速さを落としません。最高速度のままだと、半径約17.5 mの円でしか曲がれません。
  4. 脱出しても、地図と走り方が同じなので、同じ角に戻ってきます。
  5. 味方は地図を使わず、Rayは仲間との間隔を決めるためだけに使っています。

結論

敵が障害物をうまくよけられないのは、角すれすれの道を、速いまま曲がろうとするからです。まずNavMeshを戦車の大きさで焼き直し、それでもふくらむなら、大きく曲がるときにその場で回るようコードを直します。
